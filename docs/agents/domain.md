# Domain docs

Walquest uses a single-context layout:
- GLOSSARY.md at the repository root.
- Architecture decision records under docs/adr/.

Before exploring an area, read the glossary and relevant ADRs
when present. Proceed silently when they are absent.
Domain-modeling creates them as terms and decisions are resolved.

Use glossary terms consistently in issues, code, tests and proposals.
Record unresolved terminology gaps for domain-modeling.

Explicitly identify any proposal that contradicts an existing ADR,
including the ADR reference and reason to reconsider it.
